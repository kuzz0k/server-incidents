# git-03 · Слить ветку с конфликтом

**Уровень:** Junior · **Тема:** Git · **Время:** ~20 мин

## Легенда
Репозиторий `/srv/git/webapp`. Пока разработчица делала ограничение частоты запросов в ветке
`feature/rate-limit`, в `main` подняли таймаут и переименовали функцию обработки запросов.
Теперь ветку нужно влить в `main`. Тесты (`./run-tests.sh`) уже написаны под итоговое состояние.

## Задача
Влей `feature/rate-limit` в `main` так, чтобы сохранились изменения **обеих** веток и тесты прошли.

## Ограничения
- История `main` не переписывается (никаких `reset`/`push --force`), коммиты фичи должны оказаться в `main`.
- В итоговых файлах не должно остаться маркеров конфликта.

## Критерии готовности (что проверяет check)
- текущая ветка `main`, рабочая копия чистая, `./run-tests.sh` проходит
- прежний `main` и последний коммит `feature/rate-limit` — предки нового `main`
- в отслеживаемых файлах нет `<<<<<<<` / `>>>>>>>`
