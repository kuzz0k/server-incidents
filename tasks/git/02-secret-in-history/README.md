# git-02 · Секрет попал в историю Git

**Уровень:** Middle · **Тема:** Git · **Время:** ~25 мин

## Легенда
В репозитории магазина (`/srv/git/shop`, remote `origin` → `/srv/git/shop-remote.git`)
кто-то закоммитил `config/prod.env` с продовым секретом платёжного API, а через пару коммитов
«удалил» файл обычным `git rm`. Аудит нашёл секрет в истории. Ключ уже перевыпустили
(в репозитории он фиктивный: `TRAINER-FAKE-SECRET-…`), но из истории его нужно вычистить.

## Задача
1. Удали `config/prod.env` из **всей** истории, и локально, и в `origin`.
2. Сделай так, чтобы этот файл больше нельзя было случайно закоммитить (`.gitignore`), и запушь это.

## Ограничения
- Остальные файлы и их содержимое в истории сохранить (`app.py`, `config/dev.env` и т.д.).
- Это тот редкий случай, когда переписать историю и сделать force push — правильно.

## Критерии готовности (что проверяет check)
- строки секрета нет ни в одном коммите (включая reflog) локального репозитория и `origin`
- `config/prod.env` игнорируется, `.gitignore` есть в `origin/main`
- `app.py` и `config/dev.env` на `HEAD` не изменились, локальный `main` совпадает с `origin/main`
