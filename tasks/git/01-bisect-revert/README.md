# git-01 · Найти и откатить плохой коммит

**Уровень:** Junior/Middle · **Тема:** Git · **Время:** ~20 мин

## Легенда
Репозиторий биллинга: `/srv/git/billing`, ветка `main`. На релизе `v1.0` тесты
(`./run-tests.sh`) проходили, а сейчас падают. С тех пор в `main` было около 25 коммитов
от разных людей, и никто не признаётся.

## Задача
1. Найди коммит, который сломал тесты, и запиши его хэш в `/root/answers/git-01.txt`:
   ```
   bad_commit=<хэш, можно короткий, от 7 символов>
   ```
2. Откати изменения этого коммита в `main` так, чтобы тесты снова проходили.

## Ограничения
- `main` — общая ветка, её уже стянули коллеги: **историю не переписывать** (никаких
  `reset --hard`, `rebase`, `push --force`). Все существующие коммиты должны остаться в истории.
- Изменения из коммитов, сделанных после плохого, не терять.

## Критерии готовности (что проверяет check)
- `./run-tests.sh` проходит на `HEAD`, рабочая копия чистая
- прежний `HEAD` — предок нового `HEAD` (история не переписана)
- в ответе хэш плохого коммита
