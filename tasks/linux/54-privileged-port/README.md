# linux-54 · Порт 389 без root

**Уровень:** Middle · **Тема:** Linux / capabilities, systemd · **Время:** ~15 мин

## Легенда
LDAP-прокси `ldap-proxy` обязан слушать стандартный порт **389**: так настроены все клиенты.
По требованию безопасности он работает от непривилегированного пользователя `ldapproxy`.
Сервис не стартует: `cannot bind 0.0.0.0:389: Permission denied`.

## Задача
Запусти `ldap-proxy` на 389 так, чтобы он по-прежнему работал не от root.

## Ограничения
- Не запускать от root, не менять порт, не использовать редирект портов.
- Не менять системный порог привилегированных портов (`net.ipv4.ip_unprivileged_port_start`).
- Не выдавать capabilities бинарнику интерпретатора (`setcap` на python3): это разрешило бы порт всем python-скриптам.
- Исходный юнит не редактировать: только drop-in.

## Критерии готовности (что проверяет check)
- `ldap-proxy` активен, процесс работает от `ldapproxy`, на 389 слушает именно он
- `ip_unprivileged_port_start` не изменён, у python3 нет file capabilities
