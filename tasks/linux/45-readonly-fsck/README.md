# linux-45 · Диск ушёл в read-only после сбоя

**Уровень:** Middle · **Тема:** Linux / ФС, fsck · **Время:** ~20 мин

## Легенда
Ночью у гипервизора был сбой хранилища. Утром сервис загрузок `uploads-api` (порт 8045) отвечает
500, в логах `Read-only file system`. Данные лежат на отдельном диске, смонтированном в `/srv/uploads`.

## Задача
Верни диску нормальную работу на запись так, чтобы файловая система была **в порядке**,
а не просто перемонтирована в rw.

## Ограничения
- Диск не переформатировать: уцелевшие данные (`/srv/uploads/data/*.dat`) нужны.
- Повреждённые данные можно потерять, если по-другому нельзя.

## Критерии готовности (что проверяет check)
- `/srv/uploads` смонтирован с того же диска, в режиме `rw`
- в суперблоке ФС нет отметки об ошибках (`dumpe2fs -h`)
- уцелевшие файлы `data/*.dat` не изменились
- `uploads-api` активен, `/health` → 200
