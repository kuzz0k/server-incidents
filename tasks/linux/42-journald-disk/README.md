# linux-42 · Журнал systemd съел диск

**Уровень:** Junior · **Тема:** Linux / journald, логи · **Время:** ~10 мин

## Легенда
На сервере мало места, и `du` показывает, что заметную часть занимает `/var/log/journal`.
Кто-то когда-то «на всякий случай» разрешил журналу расти до нескольких гигабайт.

## Задача
1. Сократи журнал до **200 МБ** или меньше.
2. Сделай так, чтобы он больше не вырастал выше 200 МБ (настройка должна пережить перезагрузку).

## Ограничения
- Журнал должен остаться **постоянным** (на диске, переживать ребут), не `volatile` и не `none`.
- Файлы в `/var/log/journal` руками не удалять: только штатными средствами.

## Критерии готовности (что проверяет check)
- `journalctl --disk-usage` ≤ 200 МБ
- итоговое значение `SystemMaxUse` в конфигурации journald ≤ 200M
- journald работает, хранение постоянное
