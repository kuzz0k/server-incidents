# linux-24 · Разбор

## Шаги диагностики
1. `curl http://<IP>:8024/health` → `Connection refused`, `curl 127.0.0.1:8024/health` → 200.
2. `ss -ltnp | grep 8024` → `127.0.0.1:8024`: сервис слушает только loopback.
   Пакет на `<IP>:8024` приходит, но слушающего сокета на этом адресе нет, поэтому ядро отвечает RST (refused).
3. `systemctl cat metrics-api` → конфиг `/etc/metrics-api.conf` → `BIND=127.0.0.1`.

## Решение
```bash
sed -i 's/^BIND=.*/BIND=0.0.0.0/' /etc/metrics-api.conf
systemctl restart metrics-api
ss -ltnp | grep 8024     # 0.0.0.0:8024
```
Можно и `BIND=<IP сервера>`, если сервис должен быть доступен только на одном интерфейсе.

## Как не допустить снова
- Явно решать, на каком интерфейсе слушает сервис. Сервисы с метриками/админкой часто специально биндят на localhost или внутренний интерфейс.
- Если сервис должен быть доступен снаружи — закрывать лишнее фаерволом, а не bind'ом.
