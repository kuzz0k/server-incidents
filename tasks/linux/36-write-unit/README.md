# linux-36 · Написать systemd-юнит для приложения

**Уровень:** Junior · **Тема:** Linux / systemd · **Время:** ~15 мин

## Легенда
Частое задание на собеседовании: «оформи приложение как сервис». Разработчики отдали
приложение `/opt/notes-api/server.py` (запускается `python3 /opt/notes-api/server.py`)
и файл настроек `/etc/notes-api/notes-api.env`. Сейчас его запускают руками в `screen`.

## Задача
Напиши `/etc/systemd/system/notes-api.service`, чтобы приложение:
1. работало от системного пользователя `notes` (создай его, без shell и пароля);
2. брало настройки из `/etc/notes-api/notes-api.env`;
3. могло писать данные в `/var/lib/notes-api` (каталог данных из настроек);
4. само перезапускалось при падении (не позже чем через 5 секунд);
5. стартовало при загрузке сервера;
6. писало логи в journald (никаких файлов логов руками).

## Критерии готовности (что проверяет check)
- `notes-api` активен и включён, процесс работает от `notes`, `EnvironmentFile` — тот самый файл
- `curl http://127.0.0.1:8036/health` → 200
- после `kill -9` главного процесса сервис сам поднимается за 10 секунд
- `Restart` — `on-failure` или `always`, `RestartSec` ≤ 5 с
