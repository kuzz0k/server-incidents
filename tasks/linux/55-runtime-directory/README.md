# linux-55 · После ребута пропал каталог в /run

**Уровень:** Junior/Middle · **Тема:** Linux / systemd, tmpfs · **Время:** ~10 мин

## Легенда
Сервис сессий `sessiond` (порт 8055) хранит временные данные в `/run/sessiond`. После плановой
перезагрузки он отвечает 500: `data dir not writable`. Коллега вспоминает, что «в прошлый раз создал
каталог руками и всё заработало».

## Задача
Почини сервис так, чтобы каталог появлялся сам при каждом старте и после каждой перезагрузки.

## Ограничения
- Каталог должен остаться в `/run` (данные временные, на диск их писать не нужно).
- Каталог не должен быть доступен на запись всем.

## Критерии готовности (что проверяет check)
Check имитирует перезагрузку: останавливает сервис, удаляет `/run/sessiond`, применяет `systemd-tmpfiles --create` и запускает сервис. После этого:
- `/health` → 200
- каталог принадлежит `sessiond` и не доступен на запись прочим
