# linux-17 · Разбор

## Шаги диагностики
1. Найти зомби: `ps -eo pid,ppid,stat,comm | awk '$3 ~ /^Z/'` (или `top` → строка Tasks: ... zombie).
2. У всех один PPID. Смотрим родителя: `ps -o pid,ppid,stat,cmd -p <PPID>`, `pstree -p <PPID>`.
3. `systemctl status <PPID>` — процесс запущен как `legacy-batch.service`.

## Почему kill -9 не работает
Зомби уже мёртв: это запись в таблице процессов, в которой хранится код возврата для родителя.
Убрать её может только родитель, вызвав `wait()`. Если родитель умирает, зомби
«усыновляет» init (PID 1) или subreaper, и тот сразу их собирает.

## Решение
```bash
echo "parent_pid=<PPID>" > /root/answers/linux-17.txt
systemctl stop legacy-batch          # или kill <PPID>
ps -eo stat | grep -c '^Z'
```
Если родителя убивать нельзя — можно попробовать `kill -CHLD <PPID>`: процесс с обработчиком SIGCHLD соберёт детей. Этот не соберёт: в коде нет `wait()`.

## Как не допустить снова
- В коде: обрабатывать SIGCHLD / вызывать `waitpid`, или `signal(SIGCHLD, SIG_IGN)`.
- В контейнерах — init-процесс (`tini`, `docker run --init`), иначе PID 1 приложения не собирает зомби.
