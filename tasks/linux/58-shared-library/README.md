# linux-58 · cannot open shared object file

**Уровень:** Middle · **Тема:** Linux / динамические библиотеки · **Время:** ~15 мин

## Легенда
Вендор поставил сканер `vendor-scanner` (порт 8058) архивом в `/opt/vendor`: программы в `bin/`,
свои библиотеки в `lib/`. Сервис не стартует: `libvnd.so.1: cannot open shared object file`.
Файл библиотеки при этом лежит в `/opt/vendor/lib`.

## Задача
Сделай так, чтобы библиотеки вендора находились: не только для этого сервиса, но и для любых
программ вендора, которые запустят позже (например, его CLI-утилит от обычного пользователя).

## Ограничения
- Файлы вендора не переносить и не копировать в системные каталоги (`/usr/lib` и т.п.): их обновляет вендор.

## Критерии готовности (что проверяет check)
- `vendor-scanner` активен и стабилен, `/health` → 200
- `libvnd.so.1` есть в кеше динамического компоновщика (`ldconfig -p`)
- в `/usr/lib` и `/lib` нет копий библиотек вендора
