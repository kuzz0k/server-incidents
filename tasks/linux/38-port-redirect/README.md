# linux-38 · Открыть приложение на другом порту, не меняя его

**Уровень:** Middle · **Тема:** Linux / сеть, iptables · **Время:** ~15 мин

## Легенда
Старое приложение биллинга `legacy-billing` слушает захардкоженный порт **20280**, исходников нет.
Новые клиенты и балансировщик умеют ходить только на порт **8038**.

## Задача
Сделай так, чтобы запросы на порт 8038 этого сервера попадали в приложение, — и с других
машин (по IP сервера), и с самого сервера (`curl http://127.0.0.1:8038/`).

## Ограничения
- Приложение и его юнит не менять, оно продолжает слушать 20280.
- Решение на твой выбор: правила netfilter, systemd-socket-proxyd, nginx stream, socat-сервис…
  На собеседовании спросят, чем они отличаются.

## Критерии готовности (что проверяет check)
- `curl http://127.0.0.1:8038/` и `curl http://<IP сервера>:8038/` → ответ `legacy billing`
- приложение по-прежнему слушает 20280, его юнит не изменён
