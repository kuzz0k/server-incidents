# linux-02 · Разбор

## Шаги диагностики
1. `df -h /var/lib/metrics` против `du -sh /var/lib/metrics` — цифры сильно расходятся.
2. Значит, место занимает файл без имени в каталоге: он удалён, но открыт процессом.
3. `lsof +L1` (или `lsof -nP +L1 /var/lib/metrics`) — показывает `agent.log (deleted)` у процесса `python3` агента, размер ~200M.
4. Без lsof: `find /proc/*/fd -lname '*(deleted)' -printf '%p -> %l\n' 2>/dev/null`.
5. `systemctl status metrics-agent` — тот же PID.

## Решение
Inode освободится, когда последний процесс закроет дескриптор. Для агента правильный путь — перезапуск:
```bash
systemctl restart metrics-agent
df -h /var/lib/metrics
ls -l /var/lib/metrics/agent.log    # агент создал новый файл
```
Если процесс перезапускать нельзя, место можно освободить через дескриптор, не убивая процесс:
```bash
: > /proc/<PID>/fd/<N>      # обнулить удалённый файл через /proc
```
Но лог тогда так и останется «без имени», поэтому здесь нужен рестарт.

## Как не допустить снова
- Логи не удалять через `rm`, а обнулять (`truncate -s 0`) или ротировать.
- logrotate с `copytruncate` либо `postrotate` с сигналом приложению, чтобы оно переоткрыло файл.
- Мониторинг расхождения `df` и `du`.
