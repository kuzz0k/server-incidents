# docker-05 · Оптимизировать Dockerfile

**Уровень:** Middle · **Тема:** Docker / образы · **Время:** ~30 мин

## Легенда
Сервис `reports-api` (`/opt/trainer-docker/reports-api`) собирается долго, образ весит
под гигабайт, при любой правке кода заново ставятся все зависимости, а безопасники
ругаются, что процесс в контейнере работает от root.

## Задача
Перепиши `Dockerfile` (и добавь нужные файлы рядом), чтобы:
1. образ `trainer/reports-api:2.0` весил **меньше 200 МБ**;
2. процесс в контейнере работал **не от root**;
3. каталог `test-data/` (тестовые дампы) **не попадал** в образ;
4. установка зависимостей из `requirements.txt` шла **до** копирования кода (кеш слоёв);
5. приложение по-прежнему работало: `python3 app.py`, порт 8000, `/health` → 200, модуль `requests` доступен.

## Ограничения
- Не удалять `test-data/` и не менять `app.py`/`requirements.txt`.

## Критерии готовности (что проверяет check)
Check собирает `trainer/reports-api:2.0` из каталога, проверяет размер, пользователя,
отсутствие `test-data` в образе, порядок инструкций, импорт `requests` и `/health`.
